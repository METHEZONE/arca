B01
PRODUCT MOAT
INDEX ↑
ChatGPT, OpenClaw, Claude가 곧 만들면?

기능은 복제될 수 있습니다. ARCA의 방어선은 모델이 아니라 권한, 상태 전이, 외부 증거, 실패 복구가 쌓이는 commitment layer입니다.

DEEPER ANSWER
모델은 제안과 추론을 하고, 권한 판정과 상태 전이는 결정론적 코드가 맡습니다.
모델 가격과 성능이 좋아질수록 ARCA의 실행 원가는 내려가지만, 사람별 위임 경계와 완결 이력은 ARCA에 남습니다.
EVIDENCE / CALCULATION
Owned layers: sensing · Commitment Graph · delegation policy · personal/org separation · A2A identity/permission · verified closure.
OpenClaw 비교는 발표 직전 최신 공개 포지셔닝 재확인.
CLAIM BOUNDARY

“복제 불가” 또는 “세계 최초” 금지. 해자는 제품 구조와 축적 데이터의 가설이며 완결률로 증명해야 함.

LIKELY FOLLOW-UP

그럼 moat를 언제 숫자로 보여주나? → 반복 위임, evidence-verified completion, recovery success를 코호트로 측정.

MOTION → STATIC FALLBACK

모델 로고는 교체되지만 orange responsibility layer는 남는 스택. 정적: before/after 두 프레임.

PRODUCT MOAT
INDEX ↑
Instinct, Tomo, Vellum과 무엇이 다른가?

같은 personal-agent 지형을 인정하되, ARCA는 약속을 상태 객체로 만들고 외부 증거가 생길 때까지 닫는 데 제품의 중심을 둡니다.

DEEPER ANSWER
Instinct는 직접 경쟁 맵에 포함합니다. 기능 부재를 추정하지 않고 공개 evidence test로만 비교합니다.
Vellum, Tomo도 이름·포지셔닝·현재 공개 기능을 최신 공식 자료로 확인해야 합니다.
EVIDENCE / CALCULATION
비교 축: real-world sensing / commitment object / granular permission / A2A / external-evidence closure.
기준일 2026-09-21, 공식 공개자료 기준.
CLAIM BOUNDARY

타사 O/X를 단정하지 않음. credible public source 없는 매출·사용자·밸류는 생략.

LIKELY FOLLOW-UP

왜 지금 이 팀이 이길 수 있나? → lived workflow, owned stack, completion benchmark로 답함.

MOTION → STATIC FALLBACK

표의 행·열을 순차 점등하고 ARCA 행과 핵심 열은 마지막에 켬. 정적: 출처 각주가 보이는 표.

PRODUCT LOOP
INDEX ↑
Commitment Graph는 정확히 무엇인가?

대화·캘린더·행동에서 생긴 약속을 사람, 기한, 조건, 권한, 완료 증거가 연결된 살아 있는 상태 그래프로 관리하는 구조입니다.

Promise Packet 상태: detected → proposed → accepted → authorized → in_progress → evidence_submitted → verified.
한 약속의 버전과 의존성을 추적하므로 “무슨 일을 했나”보다 “무엇이 아직 닫히지 않았나”를 운영합니다.
EVIDENCE / CALCULATION
ARCA product architecture and Promise Packet design.
CLAIM BOUNDARY

현재 구현, 설계 완료, 향후 계획을 섞지 않음. 세부 데이터 스키마는 [확인 필요].

LIKELY FOLLOW-UP

LLM이 상태를 잘못 바꾸면? → 모델은 제안, 코드가 전이와 권한을 검증.

MOTION → STATIC FALLBACK

노드가 순차 점등되고 path가 성장. 정적: 상태와 필수 필드가 붙은 그래프.

Product interaction: drag-bounded delegation region.
CLAIM BOUNDARY

현재 자동화 범위의 실측 오작동률은 [확인 필요]. 완전 자율 실행을 주장하지 않음.

LIKELY FOLLOW-UP

사용자가 실수로 넓게 드래그하면? → 고위험 행동은 별도 confirmation과 취소 가능성 유지.

MOTION → STATIC FALLBACK

EVIDENCE / CALCULATION
Learning targets: extraction, intervention timing, ambiguous evidence, failure recovery.
CLAIM BOUNDARY

동의는 추론으로 생성하지 않음. 권한 원장과 상태 기계는 학습 대상이 아님.

LIKELY FOLLOW-UP

질문 감소를 어떻게 측정? → task당 clarification count와 승인 후 수정률. 현재 값 [확인 필요].

MOTION → STATIC FALLBACK

consent와 quality 두 lane의 피드백이 taste model로 흐름. 정적: 두 라벨 정의.

CLAIM BOUNDARY

모든 현실 결과를 자동 검증할 수 있다고 주장하지 않음. adapter coverage와 정확도 [확인 필요].

LIKELY FOLLOW-UP

증거가 조작되면? → source binding, hash/log, human review가 필요한 보안 설계. 구현 범위 [확인 필요].

MOTION → STATIC FALLBACK

A2A
INDEX ↑
ARCA끼리 대화하면 무엇이 달라지나?

사람끼리 반복 조율하는 비용을 줄이되, 각 ARCA는 자신이 대표하는 사람의 승인 범위 안에서만 최소 정보와 행동을 교환합니다.

DEEPER ANSWER
Commitment detection → permission/quality check → minimum request/authority/evidence packet → bilateral alignment → bounded execution → both-side closure.
B2C는 관계의 coordination tax를 줄이고, B2B는 회사 간 execution layer가 됩니다.
EVIDENCE / CALCULATION
Shared ARCA Moment; Promise Packet common atom.
CLAIM BOUNDARY

ARCAs가 사람 대신 자유롭게 결정하지 않음. 공개 A2A 네트워크 완성이나 매출을 주장하지 않음.

LIKELY FOLLOW-UP

정보가 상대 회사로 새지 않나? → packet 최소화, personal/org separation, 각 인간의 권한 검증.

MOTION → STATIC FALLBACK

두 private graph 사이에 scoped packet만 이동하고 양쪽 completion node가 lock. 정적: 교환 필드와 비공개 필드.

아닙니다. ARCA는 개인 소유 Personal Life OS이고, Company Brain AX는 같은 core를 회사 맥락에서 쓰는 첫 Work Shell입니다.

EVIDENCE / CALCULATION
Product decision: Company Brain AX = first Work Shell, not second product.
CLAIM BOUNDARY

개인 중심 thesis를 엔터프라이즈 매출 때문에 바꿨다고 말하지 않음.

LIKELY FOLLOW-UP

두 시장을 동시에 하면 산만하지 않나? → common atom과 sequencing으로 답함.

MOTION → STATIC FALLBACK

개인 graph가 Work Shell을 입고 회사 graph로 확장. 정적: same core / separate memory.

Internal deal status and first revenue record.

MOTION → STATIC FALLBACK

GTM

EVIDENCE / CALCULATION
