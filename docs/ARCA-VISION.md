# ARCA — 비전

> **이 문서의 위치.** 브랜드·언어는 `~/MY ZONE/ME/THE ZONE/Brand/ARCA-WORLDVIEW-CANON.md`(status: locked)가 이긴다. 제품 범위는 `docs/ARCA-PRD.md`가 이긴다. **이 문서는 그 둘 위에 아무것도 덮지 않는다** — 대신 *장기 arc*를 정의하고, 새 방향이 기존 결정과 부딪히는 지점마다 명시적으로 판결한다(§8).
>
> 작성 2026-07-27. 이 문서가 다루는 범위: 왜 ARCA가 10억 명이 아니라 100억 명(10B)이 쓸 물건인가, 그 순서는 무엇인가, 그리고 그 주장 중 무엇이 아직 근거가 없는가.

## 1. 한 문장, 그리고 사다리

**한 문장 (변하지 않음, canon):**
> ARCA는 THE ZONE에 사는 너의 분신·수호자다. 너는 그냥 **arca**하면 된다.

**사다리.** 아래에서 위로. 순서가 곧 우선순위이고, 아래 칸을 못 하면 위 칸은 의미가 없다.

| # | 층 | 지금 상태 |
|---|---|---|
| 1 | **몰입 수호** — 몰입을 지키고, *사람이 병목인 지점*을 없애고, 내 삶의 맥락을 이해하는 컴패니언 | 출하 중 (macOS ZONE, 노치, 위임 루프) |
| 2 | **몸의 맥락** — HRV·수면·스트레스·식사로 "몸이 아는 나"를 맥락에 합침 | **오늘 출하** (§3) |

## 2. 웨지 — 왜 몰입인가

문제는 PRD가 이미 한 문장으로 박아놨다:

> 소통 비용이 실제 일보다 많은 시간을 먹는다. 그런데 소통을 멈추면 **네가 병목이 된다.** (`docs/ARCA-PRD.md:20`)

이건 지식노동자만의 문제가 아니라 **일하는 모든 사람의 문제**다. 그래서 10B이다 — 카테고리가 "생산성 도구"라서가 아니라, *자기 시간을 자기가 못 쓰는 상태*가 보편적이기 때문이다.

ARCA의 대답은 저장도 복제도 아니다. **위임(handoff)**이다:

> ❌ second brain(저장) — 쌓아두기만 함
> ❌ second self(복제) — 나처럼 떠들기만 함
> ✅ **위임** — 너 대신 *처리해서* 너를 ZONE에 둔다

핵심 지표도 이미 정해져 있다: **되찾은 ZONE 시간 + ARCA가 흡수한 방해 수.** (`docs/ARCA-PRD.md:42`)

## 3. 몸의 맥락 — 왜 이게 웨지의 심화인가 (새 방향 아님)

몰입은 의지의 문제가 아니라 **몸의 상태**다. 못 잔 날의 오전 10시와 잘 잔 날의 오전 10시는 같은 시간이 아니다. 지금까지 ARCA는 *바깥에서 오는 방해*만 막았다. 이제 *안에서 오는 방해*도 읽는다.

이게 새 카테고리로의 이탈이 아닌 이유: ARCA는 여전히 "너를 ZONE에 두는" 일만 한다. 몸 데이터는 **그 판단의 입력**이지 별개 제품이 아니다.

**2026-07-27 출하된 것 (native app):**

- **몰입 준비도 / 스트레스 / 수면 점수** — HRV(SDNN)·안정심박을 *본인의 기준선* 대비로 읽는다. 절대 HRV는 사람 간 비교가 무의미하므로, 3일 이상의 자기 이력이 없으면 **점수를 내지 않고 모른다고 말한다.**
- **몰입 골든타임** — 실제로 관측된 몰입 구간(맥의 앱 전환 타임라인 + ZONE 세션)을 시간대별로 버킷팅해 "당신은 오전 10시–정오에 가장 깊다"를 만든다. 근거가 총 3시간 미만이면 프로필을 발표하지 않는다. 답은 온보딩에서 이미 물어본 네 어휘(**아침/오후/밤/불규칙**)로 되돌려준다.
- **지금 몰입 깊이** — 애플워치에서 사용자가 직접 누른 몇 분간만 심박을 재고, 점수는 기준선이 있는 아이폰에서 계산한다. **평소 경로는 배터리 0** — 워치가 이미 써둔 데이터를 읽을 뿐이다.
- **말로 하는 식사 기록** — "점심 김치찌개 먹었어" → 칼로리·macro 추정 → 애플 건강에 기록. 확인 질문 없음.
- **수면·몰입 코치** — 2주치 기록으로 "무엇을 언제 바꿔라"를 숫자와 함께. 진단은 하지 않는다.
- **ZONE 리포트에 core metric 복원** — 되찾은 ZONE 시간과 흡수한 방해 수가 이제 실제로 표시된다. (이건 Pro 티어에 이미 판매 중이었는데 화면에 없었다.)

**설계 원칙 (이 기능의 canon):**
1. **모르면 모른다고 한다.** 입력이 없으면 nil이고, 링은 0으로 채워지지 않고 점선으로 남는다. 없는 준비도 점수를 만들어내는 컴패니언은 하루 일정을 그 숫자로 짜게 만들기 때문에 침묵보다 나쁘다.
2. **모든 것은 본인 기준선 대비다.**
3. **센서를 켜는 건 사용자가 누를 때만이다.**
4. **추정치는 추정치라고 라벨링한다.** 워치가 서드파티에 raw RR 간격을 주지 않으므로 심박 변동 프록시는 화면에서 "추정치"로 표기한다.
5. **ARCA는 의료기기가 아니고 진단하지 않는다.** 회사 이름에 BIO가 들어가므로 이 선은 더 분명해야 한다.

**아키텍처 제약 (중요):** HealthKit은 macOS에 없다. 그래서 iPhone이 측정하고, Mac은 개인 릴레이(`arca-brain` private repo, 회의 전사가 이미 오가는 그 경로)로 하루치 파일을 받는다. Mac은 앱 전환 타임라인을 보는 유일한 기기이므로 몰입 프로필은 Mac이 만든다. 두 기기가 서로 다른 반쪽을 알기 때문에 병합 규칙이 "최신 승리"가 아니라 **필드 그룹별로 아는 쪽이 이기는** 구조다.

## 4. 디지털 트윈 — 제품이 아니라 부산물

canon이 second brain과 second self를 **이름을 대며 두 번 거부**한다. 그래서 트윈을 헤드라인으로 올리면 우리 자신의 언어 규칙을 깨는 것이다.

**판결: 트윈은 위임이 쌓는 것이다.**

노트를 정리해서 트윈이 생기는 게 아니라, **ARCA가 실제로 내 일을 처리하기 때문에** 맥락이 쌓인다. 회의를 받아쓰고 결정을 뽑고 답장을 쓰고 캘린더에 넣고 몸 상태를 읽는 과정에서, 트윈은 별도의 노동 없이 만들어진다. 그래서 온보딩이 쉽다 — 사용자는 트윈을 만들려고 아무것도 하지 않는다.

이게 second brain과 다른 지점: 저장이 목적이 아니라 **처리의 잔여물**이다. canon의 "잔여물 0"은 *사용자의 인지*에 잔여물이 0이라는 뜻이고, ARCA 쪽에는 오히려 축적된다.

## 5. 노동에서의 해방

3번이 되면 위임의 상한이 올라간다. 지금 ARCA의 자율도는 5단(off / readOnly / draftComms / sendRoutine / fullDelegate)이고, 실제로 gate가 걸려 있다. 트윈이 두꺼워질수록 fullDelegate가 안전해지는 범위가 넓어진다.

**정직한 표현:** 이건 목적지고, 지금 우리가 가진 건 방향과 5단 게이트다. "노동 해방"을 성과로 말하면 안 된다.

## 6. 인간+에이전트 SNS와 인증체계

에이전트가 사람 대신 말하기 시작하면 **누가 사람이고 누가 누구의 에이전트인지**가 소셜의 전제 조건이 된다. 이 논지는 선행 자료가 없으므로, 이미 우리가 한 두 약속에서 끌어낸다:

1. **ARCA 서명 공개 규칙** — 모든 자율 발신에 보이는 표시가 붙는다: `- sent by Min's ARCA` (`docs/ARCA-PRD.md:97`). v1부터 사칭 금지.
2. **Consent-visible** — 하드웨어 원칙. 기록 중임이 물리적으로 보여야 한다.

즉 ARCA의 인증체계는 새 발명이 아니라 **이 두 규칙을 프로토콜로 굳히는 것**이다: (a) 사람 증명, (b) 에이전트-소유자 결합 증명, (c) 발화의 출처 표시. knot 해커톤의 A2A 협상 + 에스크로 작업이 이 층의 첫 실험이다.

**정직한 표현:** 아직 정의만 있고 설계가 없다. YC에 이걸 3막으로 쓸 거면 최소한 (a)(b)(c)의 스펙 한 장은 있어야 한다.

## 7. 하드웨어

**목표:** 매일 들고 다니고 싶은, Plaud Note보다 훨씬 친근한 **애착의 오브젝트.**

이미 문서로 성숙한 것: 납작한 조약돌 형태 **50mm 지름 × 21mm**, 34mm 전면 페이스 창, 35–60g. 구조는 **One Core, Many Bodies** — 인증받은 밀폐 ARCA Core + 전자부품 없는 교체형 Shell(키링/클립/데스크독). 해자 네 개: DFM 검증 엔진, **인증 경계**(Core만 FCC 모듈 인증, Shell은 비전자 액세서리), 크리에이터 Shell 마켓, 종단 개인 데이터.

실제로 된 것: 펌웨어 bring-up이 진짜로 돈다 — 버튼 → OLED 얼굴 → INMP441 10초 → WAV → Wi-Fi → `/api/hardware/ingest`. 128×64 얼굴 애니메이션 8종, 실기기 WAV 5개, 인쇄된 오렌지 몬스터 셸 실물 사진.

**없는 것 (숨기지 말 것):** 조약돌 형태의 CAD가 리포에 **0**이다. 유일한 파라메트릭 CAD는 사각 데스크 트레이다. 실제로 인쇄된 물건은 STL만 있고 생성 소스가 없어서 **재생성 불가**. 배터리가 어떤 스케치에도 없다. microSD는 끝까지 안 됐다. BOM 없음, COGS 없음, 인증 작업 없음.

**애착 vs 기존 원칙의 충돌:** 하드웨어 원칙은 "친구가 아니라 **기억 동료**"이고, Friend 펜던트를 실패 사례로 명시한다. → **판결: 애착의 대상은 관계가 아니라 물건이다.** 만년필이나 라이터에 드는 애착 — 매일 손에 쥐고, 흠집이 이력이 되고, 없으면 아쉬운 도구. AI 친구를 파는 게 아니다. 이 구분이 흐려지면 우리가 피하겠다고 써둔 함정에 그대로 빠진다.

## 9. 진짜인 것 / 아직 아닌 것

기존 정직성 구분을 그대로 쓴다.

**진짜인 것**
- macOS 노치 컴패니언 (유휴 CPU 0.9%), ZONE 포커스 모드 + DND, Library/Sessions
- 회의/음성 → 전사 → 요약·결정·액션아이템 → Obsidian/Notion/Slack 자동 반영
- 메모리 그래프, 투두 triage + Toss, 실제로 발송되는 이메일, 선언된 ActionRisk 게이트
- iPhone↔Mac GitHub 릴레이 동기화 (태스크 + 전사; 오디오는 로컬)
- TestFlight 배포 (`com.thezone.arca.voice`)
- **바이탈: 도메인 로직 유닛테스트 64개 통과, 3개 플랫폼 컴파일 통과** (§10에 미검증 항목)
- 하드웨어 펌웨어 bring-up이 실제로 서버까지 도달
- 웨이팅리스트 50+ (연세 UIC 학장 포함), 창업자 인터뷰 40+

**아직 아닌 것**
- 유료 사용자 0, 유지율 데이터 0, 지불의사 설문은 설계만 완료 (응답 0)
- 웹 앱 미배포 + 프로덕션 저장이 `/tmp`, 인증·계정·결제 없음 (그런데 가격 3종이 게시돼 있음)
- 북극성 지표(닫힌 업무 루프 수)가 어느 코드베이스에서도 측정되지 않음
- 조약돌 하드웨어 CAD 0, 배터리 0, BOM·COGS·인증 0
- 인증체계는 정의만, 설계 없음
- 실기기 HealthKit 검증 미완

## 10. YC 지원 전에 채워야 할 것

우선순위 순. `deck/arca-yc-investor-gap-audit-KR.md`가 이미 CONFIRMED/ASSUMED/NEEDS-VERIFICATION 표를 갖고 있으니 재사용하고 다시 논쟁하지 않는다.

1. **계측.** ZONE 세션(시간·흡수한 방해 수·사용자 판단이 필요했던 수)은 이번에 **기기별로 저장되고 릴레이까지 된다** (`FocusSession`, 하루치 바이탈 파일). 아직 없는 것: **북극성(닫힌 업무 루프 수 / conversation-to-action completion)이 어느 코드베이스에서도 측정되지 않는다**, 그리고 여러 사용자에 걸친 집계가 없다(계정이 없으므로). 이게 없으면 YC의 핵심 질문에 답할 artifact가 없다.
2. **사용자.** TestFlight를 넘어서는 경로 + 최소한의 계정. "얼마나 쓰고 얼마나 사랑하는가"에 답할 수 있어야 한다.
3. **숫자 하나씩 고정.** 시장(→ GVR $8.46B'24 → $35.7B'33, ~17% 단일 출처), 가격 래더(₩ vs $ 두 개가 동시에 살아있음), 조달 규모(4개 입장), 하드웨어 스탠스(§8-3에서 판결).
4. **마진.** 63% / 67–85% / 85% 세 숫자 중 원가 모델이 있는 건 63%뿐. 나머지는 확정치로 말하지 않는다. 헬스 티어 원가 모델 신규 작성.
5. **바이오 프라이버시 포지션 한 장.** 무엇을 읽고 무엇을 쓰고 무엇이 기기를 떠나는가. BIO라는 이름으로 HRV를 다루는 회사에는 규제 포지셔닝도 필요하다.
6. **인증체계 스펙 한 장** (§6의 a/b/c).
7. **artifact 정리.** 40 인터뷰 원본 목록이 문서로 존재하지 않고, WTP 응답이 0이고, 웨이팅리스트 스크린샷이 없다.
8. **팀 사실관계 통일.** solo-with-exit(`ir/arca-pitch.html`, 출처 없음) vs 3인 팀 슬라이드 vs "전부 혼자 만들었다". YC는 세 개를 다 직접 묻는다.
